# Should You Buy Bitcoin? — the original indicator page (legacy)

> **Status: legacy / superseded.** This is the 2023 Create React App that
> originally served the Bitcoin Power Law Oscillator page. It no longer serves
> amanthakkar.com — that domain is served by
> [personal-site](https://github.com/amanthakkar/personal-site), which carries
> a modern version of the same indicator, and the model itself now lives as
> tested, open Python in
> [crypto_finance](https://github.com/amanthakkar/crypto_finance). This repo is
> kept for the record and for the analytics client described below.

## What it was

A single-page React app answering one question — *"Is it a good time to buy
Bitcoin?"* — with a chart based on the Power Law Oscillator model (with my own
tweaks for recent price action; the write-up is on
[Medium](https://medium.com/datadriveninvestor/bitcoins-power-law-oscillator-the-code-a-summary-and-a-suggested-improvement-b78b59a2bc9c)):

- **The chart was not generated by this app.** A Python script updated a static
  image (`indicator.png`) on S3 daily, and the page embedded it with a
  cache-busting timestamp. The oscillator runs from −1 to 1: dark blue ≈ cheap
  vs. the power-law trend, dark red ≈ expensive. "Buy when dark blue, sell when
  dark red" was the whole TL;DR.
- **Visitor analytics, self-hosted.** `src/analytics.js` talks to a small API
  on my home Raspberry Pi (`REACT_APP_API_BASE`, default
  `https://cloud.amanthakkar.com`): `/api/visitor-count`, `/api/stats`, and
  `/api/new-visitor?source=…` (the `?source=` parameter attributes visits to
  wherever a link was shared). A 3-minute cookie avoids double-counting a
  session; counts are stored in Redis on the Pi and no personal data is
  collected. A header component (`src/VisitorStats.js`) shows the total, with
  an expandable per-source breakdown.

## The May 2026 modernization (on `main`, never deployed)

The one substantive commit after 2023 (May 26, 2026) modernized that analytics
client: it removed the old EC2 endpoints, moved to the `/api/visitor-count` +
`/api/stats` shape above, added the source-breakdown UI, and added an offline
fallback — if the Pi backend is unreachable the header shows the last known
baseline (2,913) with a "(cached)" badge instead of breaking. **That work
exists only on `main`.** The deployed `gh-pages` build is still the October
2023 one, so none of it is live.

## Honest limitations

- **The chart source is gone:** the S3 `indicator.png` this page embeds
  returned 404 when checked on Oct 25, 2026, so even the deployed build has no
  chart today. The living implementations are the two successors linked above.
- **Pre-rename plumbing:** `package.json`'s `homepage` still names the old
  `amanbthakkar.github.io` user site and the build uses root-absolute asset
  paths, while the repo's CNAME (`www.amanthakkar.com`) no longer reflects DNS
  — personal-site owns that domain now (verified in its GitHub Pages config).
- Create React App 5 / React 18, one default CRA test, no CI. It was a
  weekend project that ran a real page for years, not maintained software.

## Run it locally

```bash
npm install
npm start            # CRA dev server
# optional: point analytics at your own backend
REACT_APP_API_BASE=https://your-api.example npm start
```

Do **not** run `npm run deploy` casually: it rebuilds, copies the stale CNAME
into the build, and republishes the `gh-pages` branch.
